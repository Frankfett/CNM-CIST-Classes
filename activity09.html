Activity 09: Incident Response Playbook

Respond to security incidents with structured methodology. Detect compromise indicators, collect evidence, contain threats, and coordinate recovery. Build effective incident response playbooks.

Introduction

Incident response is the structured process of detecting, investigating, and recovering from security incidents. When a breach occurs, rapid response minimizes damage and enables recovery.

Key incident response principles:

  • Speed: Minutes matter—faster response = smaller impact
  • Preservation: Collect evidence before systems are rebooted or cleaned
  • Coordination: Communication across teams (IT, security, management, legal)
  • Methodology: Structured approach prevents missed artifacts
  • Documentation: Every action logged for forensic and legal review
  • Playbooks: Pre-planned responses for common incidents reduce reaction time

⚠️ Incident Severity Classification

CRITICAL: Active ransomware, data exfiltration, system-wide compromise | HIGH: Confirmed intrusion, potential data loss | MEDIUM: Suspicious activity, needs investigation | LOW: Policy violation, isolated event

Detection & Initial Response

Incident Detection Indicators (IOCs)

Security teams watch for these indicators of compromise:

Severity Indicator Data Source Response
CRITICAL Ransomware encryption activity, mass file drops EDR, file monitoring, alerts Immediate isolation, incident commander activation
CRITICAL Active data exfiltration to external IP Network logs, firewall, DLP Block outbound connection, preserve data in transit
HIGH Lateral movement (pass-the-hash, Kerberoasting) Windows Event Logs, Zeek, Splunk Isolate affected domain segment, credential rotation
HIGH Privilege escalation to SYSTEM/root Process monitoring, audit logs Preserve evidence, escalate to incident commander
HIGH C2 communication to known malicious IP/domain DNS logs, proxy logs, EDR Block domain/IP, investigate host, check for beaconing
MEDIUM Suspicious process execution (cmd.exe from Office, PowerShell encoded) EDR, Event Logs, Sysmon Investigate parent process, check for exploitation
MEDIUM Brute force login attempts, failed authentication spikes Authentication logs, SIEM Lock account, reset credentials, check for compromise

Initial Response Steps (First 30 Minutes)

  1. Declare Incident: Alert incident commander and incident response team
  2. Isolate System: Disconnect from network (if CRITICAL severity)
    • Keep power ON (don't reboot, preserves RAM)
    • Unplug network cable or disable NIC (if severity allows)
  3. Preserve Evidence: Begin memory dump and network packet capture
  4. Assess Scope: Determine if incident is isolated or widespread
    • Query similar logs across infrastructure
    • Check related systems for same IOCs
  5. Document Timeline: Record exact time incident detected, actions taken
  6. Communicate: Notify management, legal, PR as appropriate

Containment Strategies

Short-Term Containment (Stop Spread)

  • Isolate Compromised Host: Unplug network, disable wireless
  • Block C2 Domains/IPs: Add firewall rules, DNS sinkhole, proxy blocks
  • Reset Compromised Credentials: Force password reset for affected accounts
  • Segment Network: Isolate affected subnets from rest of infrastructure
  • Revoke Access Tokens: Invalidate session tokens, certificates if compromised

Long-Term Containment (Eradication)

  • Remove Malware: Uninstall trojans, rootkits, backdoors
  • Close Exploitation Vector: Patch vulnerable service, disable weak protocols (SMBv1, Telnet)
  • Restore from Clean Backup: Rebuild system from known-good state
  • Verify Integrity: Hash OS files, ensure no persistence remains
  • Credential Rotation: Change all passwords, SSH keys, API tokens

💡 Containment Best Practices

  • Plan containment with minimal business impact (coordinate with operations)
  • Document all containment actions for audit trail
  • Have rollback plan in case containment breaks critical service
  • Test playbooks regularly to identify bottlenecks
  • Involve legal early for litigation hold and evidence preservation

Timeline Analysis & Artifact Correlation

Reconstructing Attack Timeline

Effective incident response requires reconstructing "who did what, when, and how." Use multiple data sources to build comprehensive timeline:

2024-03-15 08:25:33 Process injection detected EDR/Sysmon PowerShell injecting into svchost.exe

2024-03-15 08:28:12 Privilege escalation (token impersonation) Windows Event Log 4672 User: SYSTEM, Process: cmd.exe

Timeline Construction Tools

  • Plaso: Super Timeline generation from multiple log sources
  • AXIOM Timeline: Forensic timeline creation
  • Splunk: Log aggregation with temporal correlation
  • ELK Stack: Open-source log and event analysis
  • PowerShell/Python: Custom timeline merging and analysis scripts
# Generate super timeline with Plaso
log2timeline.py --parsers win_registry,sysmon output.plaso /path/to/evidence/

# Export timeline to CSV for analysis
psort.py -o csv output.plaso > timeline.csv

# Quick timeline with Python
import csv
from datetime import datetime
events = []
# Merge multiple log sources by timestamp
for log_file in ['sysmon.csv', 'network.csv', 'registry.csv']:
  with open(log_file) as f:
    events.extend(csv.DictReader(f))
events.sort(key=lambda x: datetime.fromisoformat(x['timestamp']))
# Output sorted timeline

Querying SIEM for Incident Investigation

# Splunk: Find all PowerShell executions with encoded commands
index=windows EventCode=1 Image="*powershell.exe" CommandLine="*-enc*"

# ELK: Find suspicious RDP login patterns
source:"security" AND EventID:4625 AND username:"administrator"

# Find reverse shell indicators (outbound unexpected connection)
index=network dest_port IN (4444,5555,9001,9999) action=allowed
| stats values(dest_ip) by src_ip,dest_port

# Lateral movement detection (Windows logon type 3/9)
index=windows EventCode=4624 LogonType IN (3,9)
| where dest_user!="system"
| stats dc(dest_ip) by src_ip

Incident Response Playbooks

Playbook: Ransomware Incident

Detection Trigger: Encryption activity detected, ransom note appears, file extensions changing

  1. Preparation (Day 0):
    • Notify incident commander immediately
    • Begin packet capture on affected segment
    • DO NOT REBOOT affected systems (preserve RAM)
  2. Containment (Hour 0-1):
    • Isolate affected computers from network
    • Block any C2 domains/IPs in firewall
    • Kill suspicious processes identified in EDR
    • Preserve memory dump before shutdown
  3. Investigation (Hour 1-4):
    • Identify patient zero (first infected machine)
    • Trace lateral movement path via Windows Event Logs
    • Check for web shells or persistence backdoors
    • Review firewall logs for data exfiltration
  4. Recovery (Day 1+):
    • Restore from clean backups (after confirming no backdoor)
    • Patch initial entry point (RDP, VPN, email)
    • Rotate all admin credentials
    • Re-deploy updated EDR and patch management

Playbook: Suspicious Login Activity

Detection Trigger: Brute force attempts, impossible travel, credential stuffing alerts

  1. Initial Assessment (Minutes 0-15):
    • Query authentication logs for failed/successful logins from suspicious IP
    • Check if IP is known VPN/proxy or unknown external network
    • Identify which user account was targeted
  2. Containment (Hour 0):
    • Force password reset for affected user
    • Invalidate all active sessions
    • Enable MFA if not already active
    • Add IP to blocklist (firewall or WAF)
  3. Investigation (Hour 0-2):
    • Check if attacker obtained access before detection
    • Review user's email and file access logs
    • Look for data exfiltration or lateral movement
    • Audit user's permissions and group memberships
  4. Recovery (Hour 2+):
    • If compromise confirmed, reset all credentials tied to account
    • Revoke OAuth tokens, API keys
    • Audit account activity from past 7-30 days
    • Implement additional monitoring on account

Hands-On Exercises

Exercise 1: Incident Triage and Severity Assessment

Objective: Evaluate incidents and assign severity levels.

  1. You receive 5 security alerts. For each, determine:
    • Severity level (CRITICAL, HIGH, MEDIUM, LOW)
    • Immediate containment actions needed
    • Investigation priority
  2. Example scenarios:
    • Ransomware encryption detected on file server (Answer: CRITICAL, isolate immediately)
    • Failed login attempts on admin account from new IP (Answer: HIGH, force password reset)
    • Unusual outbound HTTPS traffic to unknown domain (Answer: MEDIUM, investigate destination)
  3. Document your assessment with justification

Exercise 2: Evidence Preservation During Active Incident

Objective: Collect forensic evidence from potentially compromised system.

  1. Given compromised Windows machine, collect in this order:
    • Memory dump (before any shutdown)
    • Network connections and open ports
    • Running processes and loaded DLLs
    • Registry hives (SYSTEM, SAM, SECURITY, NTUSER.DAT)
    • Event logs
    • Disk image (full bitwise copy)
  2. Use tools:
    • Memory: DumpIt or Volatility
    • Network: netstat -ano, Get-NetTCPConnection
    • Processes: Get-Process -IncludeUserName
    • Registry: reg export HKLM\SYSTEM system.hive
    • Disk: dd or imaging tool
  3. Calculate MD5/SHA-256 hashes of all evidence files
  4. Create chain of custody documentation

Exercise 3: Timeline Construction & Artifact Correlation

Objective: Build comprehensive timeline from multiple data sources.

  1. You're provided with:
    • Windows Event Logs
    • Sysmon event capture
    • Network traffic PCAP
    • EDR alert logs
    • Web proxy logs
  2. Create unified timeline showing:
    • Initial access vector (phishing, RDP brute force, etc.)
    • Command execution and file drops
    • Lateral movement steps
    • Data exfiltration or persistence installation
    • Attack end (if detected)
  3. Use Plaso or manual timeline tool to merge logs
  4. Export as CSV and create visual timeline

Exercise 4: Containment Strategy Development

Objective: Create containment plan for active incident.

  1. Scenario: Trojan discovered on 15 systems in Finance department, C2 beaconing to external IP
  2. Develop short-term containment (0-1 hour):
    • Isolate affected systems
    • Block C2 domain/IP
    • Reset potentially compromised credentials
  3. Develop long-term containment (1-24 hours):
    • Rebuild systems from clean backups
    • Identify and close initial access point
    • Patch vulnerability or disable weak service
  4. Consider business impact:
    • How long can Finance department be offline?
    • What's the cost of slow recovery vs. thorough investigation?
    • Document all tradeoffs

Exercise 5: Incident Response Playbook Creation

Objective: Write playbook for your organization's common incidents.

  1. Choose incident type (ransomware, data breach, insider threat, supply chain, etc.)
  2. Document playbook sections:
    • Trigger: What alerts indicate this incident?
    • Preparation: What tools, training, and capabilities needed?
    • Detection: Specific IOCs to watch for
    • Response: Step-by-step containment and investigation
    • Recovery: How to restore and verify integrity
    • Communication: Who to notify and escalation paths
    • Lessons Learned: Post-incident review process
  3. Include decision trees and conditional logic
  4. Test playbook against hypothetical scenario

Key Takeaways

🎯 Remember These Points

  • Speed matters—incident response minutes matter more than hours
  • NIST framework (Preparation, Detection, Containment, Eradication, Recovery) provides structured approach
  • Preserve evidence before taking containment actions (memory, disk, network traffic)
  • Triage by severity to prioritize resources (CRITICAL incidents get immediate response)
  • Timeline analysis using multiple data sources reveals full attack narrative
  • Playbooks reduce response time and ensure consistent procedures
  • Contain short-term to stop spread, then eradicate long-term for complete removal
  • Communication and coordination across teams is as important as technical response
