Introduction

Malware analysis is the process of understanding malicious software behavior, capabilities, and impact. Security teams use malware analysis to:

  • Threat Intelligence: Generate IOCs and publish threat reports
  • Incident Response: Understand what happened and how to contain it
  • Defense: Block malware signatures and behavioral patterns
  • Forensics: Reconstruct attack timeline and attacker intent
  • Attribution: Link malware to known threat actors

Malware analysis uses two primary approaches:

  • Static Analysis: Examine files without execution (safe, reversible)
  • Dynamic Analysis: Execute malware in sandbox and observe behavior (risky, requires isolation)

⚠️ Critical Safety Warning

Never execute malware on production systems. All malware analysis MUST occur in isolated sandbox environments (VirtualBox, QEMU, cloud sandboxes). Malware can spread via network, USB, and storage. Single mistake can compromise your entire system and network.

Static Analysis Techniques

1. File Metadata & Header Analysis

Examine PE headers and file properties for clues about compilation, dependencies, and suspicious indicators:

  • Timestamps: Compilation time (reveals when malware was built)
  • Subsystem: Console vs. GUI (behavioral hints)
  • Sections: Suspicious names (.text, .data vs. .packed, .upack, .rsrc)
  • EntryPoint: Where execution starts (unusual values suggest packers)
  • Import Address Table (IAT): What Windows APIs are imported (CreateProcess, RegSetValue, etc.)
# Examine file with exiftool
exiftool malware.exe

# PE header analysis with pefile (Python)
import pefile
pe = pefile.PE('malware.exe')
print(pe.FILE_HEADER.TimeDateStamp)
print([imp.dll for imp in pe.DIRECTORY_ENTRY_IMPORT])

# Quick strings extraction
strings malware.exe | grep -E '(http|registry|\.exe)'

2. String Analysis

Extract readable strings to identify:

  • URLs and domains for C2 communication
  • Registry paths for persistence
  • File paths and system calls
  • Debugging symbols or developer hints
  • Packed/encrypted payload signatures

3. Entropy Analysis

Measure randomness in binary sections to detect encryption/compression:

  • Low entropy (0-3): Normal code or data
  • High entropy (6-8): Encrypted, compressed, or packed payload
  • Sections with high entropy suggest obfuscation attempts

4. Import Table Analysis (IAT)

Examine Windows API imports to predict functionality:

  • CreateProcessA/W: Process injection or spawning
  • RegOpenKey/RegSetValue: Registry modification (persistence)
  • InternetOpenUrlA/W: Network communication
  • GetModuleHandle/GetProcAddress: Runtime API loading (evasion)
  • WriteFile/CreateFileA: File system access

5. Disassembly & Reverse Engineering

Use disassemblers to understand code logic:

  • IDA Pro: Industry standard, powerful analysis, expensive
  • Ghidra: NSA-released, free, excellent decompiler
  • Radare2: Open-source, CLI-driven, scriptable
# Launch Ghidra for reverse engineering
ghidra_headless . -import malware.exe -postScript AnalysisScript.py

# Calculate entropy (Python)
import math
from collections import Counter
def entropy(data):
  counts = Counter(data)
  prob = [c/len(data) for c in counts.values()]
  return -sum(p * math.log2(p) for p in prob)

with open('malware.exe', 'rb') as f:
  print(entropy(f.read()))

Behavioral Monitoring

During dynamic analysis, monitor:

  • File System: Created, modified, or deleted files (Procmon)
  • Registry: Registry key modifications (Procmon)
  • Network: DNS queries, HTTP requests, connections (Wireshark, Burp)
  • Process Behavior: Spawned processes, injected DLLs (Process Hacker)
  • Memory: Suspicious allocations and modifications (WinDbg)

Dynamic Analysis Tools

  • Procmon (Process Monitor): Real-time file system and registry monitoring
  • Wireshark: Network traffic capture and analysis
  • WinDbg: Kernel debugger for live analysis
  • Process Hacker: Advanced process and thread viewer
  • Regshot: Registry snapshot comparison (before/after)
# Capture network traffic (Linux)
tcpdump -i eth0 -w malware_traffic.pcap
wireshark malware_traffic.pcap

# Monitor system calls (Linux)
strace -e trace=open,read,write,execve -o trace.log ./malware

# Monitor with Procmon (Windows, requires admin)
procmon.exe /beginfiltering /noconnect

💡 Dynamic Analysis Best Practices

  • Isolate sandbox from network (air-gap or firewall rules)
  • Start packet capture BEFORE execution
  • Take snapshot of clean system state before running malware
  • Use fake DNS responses to avoid real C2 callback
  • Allow malware to run for 5-10 minutes to observe full behavior
  • Revert to snapshot after analysis (never "clean up" live)

Common Malware Indicators (IOCs)

IOC Type Example Use Case
File Hash MD5/SHA-1/SHA-256 Identify exact file samples, blocking
Domain malicious.com, c2.attacker.ru Block C2 communication via DNS/firewall
IP Address 192.168.1.100, 203.0.113.42 Block network-level C2 callbacks
Registry Key HKLM\Software\Microsoft\Windows\Run Detect persistence mechanisms
File Path C:\Users\%USERNAME%\AppData\malware.exe Identify where malware installs itself
Mutex Global\MalwareMutex_12345 Detect running malware instances
Service Name WindowsUpdateService Masqueraded persistence services
User-Agent Mozilla/5.0 (Custom C2 Framework) Block C2 HTTP communication

Hands-On Exercises

Exercise 1: Setup Malware Analysis Sandbox

Objective: Create isolated, reproducible malware analysis environment.

  1. Create clean Windows 7/10 VM with VirtualBox:
    • 2GB+ RAM, 20GB disk
    • Disable automatic updates
    • Disable Windows Defender/UAC
  2. Install analysis tools:
    • Process Monitor (Procmon)
    • Wireshark
    • Process Hacker
    • Regshot
    • IDA Pro Free or Ghidra
  3. Configure network isolation:
    • NAT adapter only (no host network access)
    • Block outbound traffic in firewall
    • Or air-gap VM completely (no network adapter)
  4. Create snapshot: Right-click VM → Snapshots → Take Snapshot (name: "Clean State")

Exercise 2: Static Analysis of Sample Malware

Objective: Perform deep static analysis without execution.

  1. Obtain malware sample (from HackTheBox, Cuckoo samples, or VirusTotal)
  2. Calculate file hashes:
    • md5sum malware.exe
    • sha256sum malware.exe
  3. Extract strings: strings malware.exe | sort | uniq > strings.txt
  4. Analyze PE headers with Ghidra:
    • Open in Ghidra
    • Review imports (API functions)
    • Check sections and entropy
  5. Look for indicators:
    • Suspicious imports (CreateProcess, RegSetValue)
    • Embedded URLs or domains
    • File paths or registry keys
    • Encryption/compression (high entropy sections)
  6. Document findings in analysis report

Exercise 3: Disassembly & Reverse Engineering

Objective: Understand malware code logic via disassembly.

  1. Open malware sample in Ghidra or IDA Pro
  2. Navigate to entry point and main function
  3. Trace suspicious function calls:
    • CreateProcessA → process injection
    • RegOpenKeyExW → registry modification
    • InternetOpenUrlA → C2 communication
  4. Analyze control flow:
    • Conditional jumps (if-else logic)
    • Loops (repeated malicious actions)
    • Function calls (dependencies)
  5. Add comments and labels for clarity
  6. Export function list and call graph

Exercise 4: Dynamic Analysis in Sandbox

Objective: Execute malware safely and observe runtime behavior.

  1. Restore sandbox VM to clean snapshot
  2. Start monitoring tools:
    • Open Procmon (System Internals)
    • Start Wireshark packet capture
    • Open Process Hacker
  3. Copy malware sample into sandbox via shared folder
  4. Execute malware and observe:
    • New processes spawned
    • Files created/modified
    • Registry modifications
    • Network connections attempted
  5. Let it run for 5-10 minutes to capture full behavior
  6. Export logs and PCAP for analysis
  7. Revert to clean snapshot (DO NOT shut down normally)

Exercise 5: IOC Extraction & Threat Report

Objective: Extract actionable intelligence from analysis.

  1. Compile IOCs from static and dynamic analysis:
    • File hash (MD5, SHA-1, SHA-256)
    • Domains/URLs (from strings and network capture)
    • IP addresses (C2 servers)
    • Registry keys modified
    • File paths created
    • Mutexes
  2. Map malware behavior to MITRE ATT&CK framework:
    • Initial Access
    • Persistence (registry, scheduled tasks)
    • Defense Evasion
    • Command & Control
    • Exfiltration
  3. Create comprehensive report including:
    • Executive summary
    • Technical analysis (static & dynamic)
    • IOCs and detection signatures
    • MITRE ATT&CK mapping
    • Remediation recommendations

Key Takeaways

🎯 Remember These Points

  • Static analysis is safe and quick; dynamic analysis provides complete behavior picture
  • NEVER run malware on production systems—always use isolated sandbox with no network access
  • File hashes, domains, and registry keys are critical IOCs for blocking and detection
  • MITRE ATT&CK mapping helps correlate malware behavior to known threat techniques
  • Disassembly with Ghidra/IDA reveals attacker intent and hidden capabilities
  • Behavioral artifacts (network traffic, file creation) are often more useful than code analysis
  • Entropy analysis detects packing and encryption (signs of obfuscation)
  • Good malware analysis reports enable better defense and incident response
