Activity 07: Memory Forensics Analysis

Extract and analyze volatile memory (RAM) from running systems. Uncover hidden malware, recover deleted data, and reconstruct system activity from memory dumps.

Difficulty Advanced
Duration 5-6 hours
Tools Required Volatility, WinDbg, DumpIt

Learning Objectives

📚 What You'll Learn

  • Understand volatile memory structure and importance in forensics
  • Capture memory dumps from running systems safely

  • Extract network connections, open files, and registry hives
  • Detect rootkits and kernel-level malware
  • Recover deleted data from memory
  • Reconstruct user activity and timeline analysis

Introduction

Volatile memory (RAM) is temporary storage that holds active processes, network connections, encryption keys, and sensitive data. Unlike disk storage, RAM is erased when power is lost, making it critical to capture during incident response.

Memory forensics provides unique insights:

  • Live Process Analysis: See what's actually running in memory
  • Rootkit Detection: Identify kernel-level malware invisible to file system analysis
  • Encryption Keys: Recover keys still resident in memory
  • Hidden Artifacts: Find evidence deleted from disk but still in RAM
  • Timeline Reconstruction: Piece together user activity and attack sequence

⚠️ Important Note

Memory capture can be resource-intensive and may impact system stability. Always perform on non-critical systems or with proper coordination during incident response. Live memory analysis should be performed with extreme caution.

Memory Architecture and Volatility

Memory Structure Overview

Windows memory is organized hierarchically with kernel structures at the lowest level:

  • Kernel Memory: Reserved for OS, drivers, and kernel data structures
  • User Memory: Application memory space
  • Page File: Virtual memory extension on disk
  • System Structures: Process table, VAD trees, handle tables

Volatility Framework

Volatility is the industry-leading framework for memory dump analysis. It provides plugins for extracting artifacts:

  • Process Analysis: pslist, pstree, psscan (find hidden processes)
  • Network Artifacts: netscan, connections, sockets
  • File Handling: filescan, handles (open files and registry keys)
  • Rootkit Detection: rootkitscan, malfind (detect injected code)
  • Registry Analysis: hivelist, printkey (extract registry hives)
  • Malware Recovery: vaddump, memdump (dump suspicious regions)

Key Memory Artifacts

Artifact Type Volatility Plugin Forensic Value
Processes pslist, pstree, psscan Identify running applications, find injected code, parent-child relationships
Network Connections netscan, connections Detect C2 communications, data exfiltration, network beacons
Open Files filescan, handles See what files were accessed, temporary files, handles to resources
DLLs and Modules dlllist, ldrmodules Detect unhook attempts, anomalous library loading, code injection
Injected Code malfind, hollowfind Find shellcode, process hollowing, rootkits, hidden malware
Rootkits rootkitscan, driverscan Detect kernel-level rootkits, hidden processes, hooked functions
Registry Hives hivelist, printkey Extract USER, SAM, SYSTEM hives with current state
Browser Artifacts iehistory, firefoxcache Browser history, cookies, cached pages in memory

Volatility Basic Workflow

# 1. Identify the image profile (OS/version)
volatility -f memory.dump imageinfo

# 2. List running processes
volatility -f memory.dump --profile=Win7SP1x64 pslist

# 3. Look for hidden processes (kernel-level hiding)
volatility -f memory.dump --profile=Win7SP1x64 psscan

# 4. Analyze network connections
volatility -f memory.dump --profile=Win7SP1x64 netscan

# 5. Find injected code and rootkits
volatility -f memory.dump --profile=Win7SP1x64 malfind
volatility -f memory.dump --profile=Win7SP1x64 rootkitscan

# 6. Extract files and registry hives
volatility -f memory.dump --profile=Win7SP1x64 filescan | grep -i .exe
volatility -f memory.dump --profile=Win7SP1x64 hivelist

# 7. Dump suspicious process memory
volatility -f memory.dump --profile=Win7SP1x64 memdump -p [PID] -D ./dump/

Capturing Memory Dumps

# Windows: Using DumpIt (must run as Administrator)
dumpit.exe
# Creates DumpIt.sys in current directory

# Linux: Using LiME
sudo insmod lime.ko "path=/home/output/memory.dump format=lime"

# Verify captured dump
file memory.dump
ls -lh memory.dump
md5sum memory.dump

💡 Pro Tips

  • Always identify the profile first—analysis depends on correct profile selection
  • Use psscan in addition to pslist to find processes hidden by rootkits
  • Cross-reference artifacts: if netscan shows suspicious IP, find corresponding process in pslist
  • Dump suspicious process memory for deeper analysis with IDA Pro or Ghidra
  • Extract volatility output to CSV for better correlation and timeline building

Hands-On Exercises

Exercise 1: Memory Dump Capture

Objective: Safely capture memory from a running lab system.

  1. Prepare isolated lab VM with known state
  2. Install memory capture tool (DumpIt for Windows or LiME for Linux)
  3. Execute capture:
    • Windows: Run DumpIt.exe as Administrator
    • Linux: Load LiME kernel module with output path
  4. Verify dump captured:
    • Check file size (should be close to system RAM)
    • Verify dump integrity with hash
    • Document capture time and system state

Exercise 2: Image Profile Identification

Objective: Identify OS version and architecture of memory dump.

  1. Run imageinfo plugin: volatility -f dump.mem imageinfo
  2. Note suggested profiles (usually multiple options)
  3. Identify key information:
    • Windows version and service pack
    • Architecture (32-bit or 64-bit)
    • Suggested Volatility profile
  4. Document selected profile for all subsequent analysis

Exercise 3: Process Analysis and Hidden Process Detection

Objective: Identify running processes including hidden ones.

  1. List processes from PEB (visible to Windows):
    • volatility -f dump.mem --profile=Win7SP1x64 pslist
    • Note parent-child relationships
  2. Scan process objects (find hidden processes):
    • volatility -f dump.mem --profile=Win7SP1x64 psscan
    • Compare with pslist output
    • Identify processes in psscan but not in pslist (hidden)
  3. Analyze suspicious processes:
    • Document command lines and working directories
    • Note unusual parent-child relationships (explorer.exe spawning cmd.exe, etc.)

Exercise 4: Network Forensics and IOC Detection

Objective: Extract network connections and identify C2 communication.

  1. Extract all network connections:
    • volatility -f dump.mem --profile=Win7SP1x64 netscan
  2. For each connection, identify:
    • Source and destination IP addresses
    • Port numbers and protocols
    • Associated process ID and name
    • Connection state (ESTABLISHED, LISTENING, etc.)
  3. Cross-reference with known malicious IPs/domains (threat intel)
  4. Correlate with process analysis to build attack narrative

Exercise 5: Malware Detection and Code Injection Analysis

Objective: Identify injected code and rootkits in memory.

  1. Scan for injected code:
    • volatility -f dump.mem --profile=Win7SP1x64 malfind
    • Look for executable pages in unusual locations
    • Identify VAD regions with EXECUTE access
  2. Detect rootkits:
    • volatility -f dump.mem --profile=Win7SP1x64 rootkitscan
    • Check for hooked system calls and functions
    • Look for hidden modules and drivers
  3. Dump suspicious regions:
    • volatility -f dump.mem --profile=Win7SP1x64 memdump -p [PID] -D ./dumps/
    • Analyze dumped regions with IDA Pro or Ghidra

Key Takeaways

🎯 Remember These Points

  • Volatile memory provides critical evidence that disk analysis cannot reveal
  • Memory captures must be done immediately—data is lost on power-down
  • Correct profile identification is essential for accurate Volatility analysis
  • psscan finds hidden processes; pslist only shows visible ones
  • Network connections in memory reveal active C2 communication
  • malfind and rootkitscan detect techniques invisible to file-based scanning
  • Cross-referencing artifacts builds stronger forensic narratives
  • Memory forensics is critical for detecting advanced persistent threats (APTs)
