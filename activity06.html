Activity 06: Forensic Evidence Collection

Master the critical first step of digital forensics. Learn proper evidence handling, chain of custody procedures, and preservation techniques to ensure admissibility in legal proceedings.

Learning Objectives

  • Create forensically sound disk images
  • Maintain proper evidence storage and security

Introduction

Digital forensics is the science of uncovering and interpreting electronic data. The first and most critical step is evidence collection and preservation. Improper evidence handling can render findings inadmissible in court, potentially destroying an entire investigation.

Evidence collection involves:

  • Identification: Recognizing what constitutes evidence
  • Collection: Safely acquiring evidence without modification
  • Preservation: Maintaining evidence integrity throughout analysis
  • Documentation: Creating detailed records of all handling

⚠️ Legal Compliance

Evidence collected improperly may be ruled inadmissible in court. Always follow proper procedures, maintain chain of custody, and consult with legal counsel. This activity uses simulated scenarios only—real forensics requires proper authorization and legal oversight.

Disk Imaging with dd

# List available disks
sudo fdisk -l

# Create forensic image of /dev/sdb
sudo dd if=/dev/sdb of=/mnt/forensics/evidence.img bs=4M status=progress conv=noerror,sync

# Create compressed image with verification
sudo dd if=/dev/sdb bs=4M conv=noerror,sync | gzip > evidence.img.gz

# Verify image integrity with hash
sudo md5sum /dev/sdb > evidence.md5
md5sum evidence.img >> evidence.md5
md5sum -c evidence.md5

Hash Calculation and Verification

# Calculate MD5 hash of original disk
sudo md5sum /dev/sdb > disk_hash.md5

# Calculate MD5 hash of image
md5sum evidence.img > image_hash.md5

# Verify hashes match
md5sum -c disk_hash.md5
md5sum -c image_hash.md5

# SHA-256 for stronger verification
sha256sum /dev/sdb > disk_sha256.txt
sha256sum evidence.img > image_sha256.txt
diff disk_sha256.txt image_sha256.txt

💡 Pro Tips

  • Always use write blockers when handling evidence drives
  • Create multiple images of critical evidence for redundancy
  • Use both MD5 and SHA-256 hashes for integrity verification
  • Document everything: time, date, person, method, tool versions
  • Store images in forensically sound format (E01, dd, raw)
  • Keep chain of custody forms with evidence at all times

Chain of Custody

Chain of custody is a legal record documenting everyone who has handled evidence and when. It's critical for maintaining evidence admissibility in court.

Hands-On Exercises

Exercise 1: Evidence Preparation

Objective: Prepare a forensic collection kit and environment.

  1. Gather required materials:
    • USB write blockers
    • Forensic imaging tools (dd, FTK Imager)
    • External storage (verified clean)
    • Chain of custody forms
    • Evidence labels and markers
    • Anti-static bags and materials
  2. Set up isolated forensic workstation:
    • Disconnect from network
    • Verify no unnecessary applications running
    • Document system configuration and hash OS files
  3. Create documentation kit with blank forms

Exercise 2: Evidence Identification and Documentation

Objective: Identify evidence and create detailed documentation.

  1. Identify sample evidence items (simulated lab scenario)
  2. For each item, document:
    • Physical description and condition
    • Serial numbers and identifiers
    • Current location and storage condition
    • Potential data sources (HDD, USB, RAM)
    • Any visible damage or modifications
  3. Photograph evidence with scale and identifying markers
  4. Create initial inventory list

Exercise 3: Forensic Disk Imaging

Objective: Create and verify forensic disk images using dd.

  1. Using a lab USB drive as evidence:
    • Connect via write blocker to isolated system
    • Identify device name: sudo fdisk -l
  2. Create forensic image:
    • sudo dd if=/dev/sdb of=/path/to/evidence.img bs=4M status=progress conv=noerror,sync
  3. Calculate hashes for both original and image:
    • sudo md5sum /dev/sdb > original.md5
    • md5sum evidence.img > image.md5
  4. Verify hash match and document results

Exercise 4: Chain of Custody Documentation

Objective: Create and maintain proper chain of custody records.

  1. Complete chain of custody form for collected evidence:
    • Item identification and description
    • Collection date, time, and location
    • Collector name and credentials
    • Hash values (MD5 and SHA-256)
  2. Simulate transfer of evidence:
    • Initial receiver signs and documents transfer
    • New receiver documents purpose of access
    • Create transfer entries for multiple handoffs
  3. Document storage conditions and security measures

Exercise 5: Hash Verification and Evidence Integrity

Objective: Understand and practice hash verification for evidence integrity.

  1. Calculate multiple hash algorithms for evidence:
    • MD5: md5sum evidence.img
    • SHA-256: sha256sum evidence.img
    • Document all hashes in chain of custody
  2. Verify image integrity:
    • Calculate hash of original again: sudo md5sum /dev/sdb
    • Compare to image hash—should be identical
    • Document verification results
  3. Understand hash collision risks and mitigation:
    • MD5 is faster but theoretically vulnerable
    • SHA-256 is slower but cryptographically stronger
    • Best practice: use both for redundancy

Key Takeaways

🎯 Remember These Points

  • Evidence collection is the foundation of digital forensics—improper handling ruins investigations
  • Chain of custody is a legal requirement and must be maintained meticulously
  • Hash verification ensures evidence integrity and prevents tampering claims
  • Write blockers prevent accidental modification of original evidence
  • Forensic images should be created before any analysis
  • Documentation must be thorough, timestamped, and signed by all handlers
  • Multiple hash algorithms (MD5 + SHA-256) provide stronger assurance
  • Evidence storage must be secure and environmental conditions maintained
