Introduction

Security hardening is the practice of reducing system vulnerability by eliminating unnecessary services, closing ports, applying security patches, and configuring secure defaults. Hardening is a proactive defense strategy—it makes systems harder to compromise by reducing the attack surface.

Hardening follows the principle of defense-in-depth: multiple security layers ensure that if one control fails, others still provide protection.

Why Hardening Matters

  • Reduces Attack Surface: Fewer services = fewer exploitable vulnerabilities
  • Slows Attackers: Hardened systems are more difficult and time-consuming to compromise
  • Limits Lateral Movement: Network segmentation prevents attackers from spreading
  • Enables Faster Detection: Unusual activity stands out on hardened baselines
  • Improves Compliance: Satisfies security standards and regulations (CIS, NIST, PCI-DSS)

💡 The 70/30 Rule

Security research shows that ~70% of breaches exploit known vulnerabilities with publicly available patches. Hardening (patching, disabling services, secure configs) prevents the majority of breaches. The remaining 30% require advanced detection and response capabilities.

Operating System Hardening

Windows Hardening

  • Disable Unnecessary Services: Remove SMBv1, Telnet, SNMP (attack vectors)
  • Windows Defender: Enable real-time protection and cloud-based detection
  • Windows Firewall: Default-deny for inbound, enable outbound filtering
  • User Account Control (UAC): Require elevation for privileged operations
  • Security Baseline: Apply CIS Benchmarks or DISA STIGs via Group Policy
  • PowerShell Logging: Enable ScriptBlockLogging and Module Logging for visibility
  • Audit Policy: Enable advanced audit policies (Process Creation, Network Connection)
  • Disk Encryption: BitLocker for confidentiality of data at-rest
# Disable SMBv1 (Windows)
Set-SmbServerConfiguration -EnableSMB1Protocol $false -Force

# Enable PowerShell script logging
New-ItemProperty -Path "HKLM:\Software\Policies\Microsoft\Windows\PowerShell\ScriptBlockLogging" -Name "EnableScriptBlockLogging" -Value 1

# Apply CIS Benchmark via Group Policy (domain)
gpupdate /force

# Enable Windows Defender real-time protection
Set-MpPreference -DisableRealtimeMonitoring $false

Linux Hardening

  • File Permissions: Principle of least privilege (644 for config, 755 for executables)
  • SELinux/AppArmor: Mandatory Access Control (MAC) to restrict process capabilities
  • SSH Hardening: Disable password auth, use key-based auth only, restrict root login
  • Firewall (UFW/iptables): Default-deny inbound, allow only necessary ports
  • Sudo Configuration: Restrict sudo access, require password, log all sudo usage
  • Kernel Parameters: Disable IP forwarding (sysctl.conf), enable ASLR, restrict kernel modules
  • Regular Patching: Keep kernel, libraries, and packages up-to-date
  • Audit Logging: Enable auditd for system call monitoring
# SSH hardening (/etc/ssh/sshd_config)
PermitRootLogin no
PubkeyAuthentication yes
PasswordAuthentication no
X11Forwarding no
Port 2222 # Non-standard port

# Apply firewall rules (UFW)
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable

# Kernel hardening (sysctl.conf)
net.ipv4.ip_forward = 0
kernel.yama.ptrace_scope = 2 # Restrict ptrace
kernel.kptr_restrict = 2 # Hide kernel pointers

Network Hardening

Network Segmentation

Divide network into security zones to limit lateral movement:

  • DMZ: Public-facing servers (web, mail, DNS) isolated from internal network
  • Internal Network: User workstations and internal services
  • Admin Network: Privileged access workstations (PAW) for admin tasks
  • IoT/Guest Network: Untrusted devices isolated from critical infrastructure
  • Data Center: Database and file servers with restricted access

Firewall & Access Control

  • Default-Deny Posture: Deny all traffic by default, allow only necessary flows
  • Application Layer Filtering: Inspect traffic for malicious payloads
  • VPN Requirements: Require VPN for remote access (zero-trust networks)
  • Intrusion Prevention: Block known attack signatures and abnormal traffic

DNS & Threat Intelligence

  • DNS Filtering: Block known malicious domains and C2 infrastructure
  • DNSSEC: Prevent DNS spoofing attacks
  • Threat Intelligence Feeds: Update IDS/IPS with latest IOCs
# Basic firewall rules (iptables)
sudo iptables -P INPUT DROP
sudo iptables -P FORWARD DROP
sudo iptables -P OUTPUT ACCEPT

# Allow SSH
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT

# Allow established connections
sudo iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

# Save rules (Ubuntu/Debian)
sudo ufw enable

Automated Hardening with Ansible

Deploy security configurations at scale:

# Ansible playbook: hardening.yml
---
- hosts: all
  tasks:
    - name: Disable SMBv1
      win_powershell:
        script: 'Set-SmbServerConfiguration -EnableSMB1Protocol $false -Force'

    - name: Enable Windows Firewall
      win_firewall:
        state: enabled

    - name: Apply CIS Benchmark
      win_secpol:
        section: 'Account Lockout Policy'
        key: 'LockoutDuration'
        value: 30

# Run playbook: ansible-playbook hardening.yml -i inventory.ini

Hands-On Exercises

Exercise 1: OS Hardening Audit

Objective: Audit a system against security baselines.

  1. Choose a baseline (CIS Benchmark, DISA STIG, or NIST)
  2. Audit current system configuration:
    • Running services and open ports
    • User accounts and permissions
    • Firewall and security policy settings
    • Encryption and logging status
  3. Identify gaps (non-compliant settings)
  4. Document findings in audit report
  5. Prioritize remediation by severity

Exercise 2: Windows Hardening Implementation

Objective: Apply security hardening to Windows system.

  1. Disable unnecessary services:
    • SMBv1, Telnet, SNMP, unnecessary RPC services
    • Remote Desktop (if not needed)
  2. Configure Windows Defender and Firewall
  3. Enable PowerShell logging and audit policies
  4. Apply Group Policy security templates
  5. Enable BitLocker encryption
  6. Re-scan with Nessus to verify improvements

Exercise 3: Linux Hardening Implementation

Objective: Harden Linux server against common attacks.

  1. Configure SSH hardening:
    • Disable password authentication
    • Restrict root login
    • Use non-standard port (e.g., 2222)
  2. Configure firewall (UFW/iptables):
    • Default-deny inbound
    • Allow only necessary ports
  3. Harden kernel parameters (sysctl.conf)
  4. Enable SELinux or AppArmor
  5. Set correct file permissions (644/755 standard)
  6. Verify with automated scanning

Exercise 4: Network Segmentation Design

Objective: Design network security zones.

  1. For a given organization (e.g., small business, hospital, university):
    • Identify critical assets (databases, file servers, HR systems)
    • Design network zones (DMZ, internal, admin, guest, data center)
  2. Create firewall rule matrix:
    • Source zone → Destination zone → Allowed protocols/ports
    • Example: DMZ ↔ Internal: Only HTTP/HTTPS, port 443
  3. Implement segmentation via VLANs or physical separation
  4. Document security zones and data flows

Exercise 5: Hardening Automation with Ansible

Objective: Create playbook for consistent hardening deployment.

  1. Write Ansible playbook covering:
    • Patch management (yum/apt update)
    • Disable unnecessary services
    • Firewall configuration
    • SSH hardening
    • User account policies (password length, expiry)
  2. Deploy to multiple systems in lab environment
  3. Verify compliance with automated scanning
  4. Version control playbook in Git

Key Takeaways

🎯 Remember These Points

  • Hardening reduces attack surface—fewer services = fewer vulnerabilities
  • Defense-in-depth means multiple layers (OS, network, app, crypto, monitoring)
  • ~70% of breaches exploit known vulnerabilities—patches and baselines matter most
  • CIS Benchmarks, DISA STIGs, and NIST guidelines provide tested hardening standards
  • Network segmentation limits lateral movement and contains breaches
  • Default-deny firewall policies are more secure than default-allow
  • Automation (Ansible, Terraform) enables consistent hardening at scale
  • Hardening is ongoing—continuous scanning and remediation prevent regression
